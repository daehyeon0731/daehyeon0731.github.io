그래프 뷰 — 글을 노드로 잇기

Obsidian 그래프 뷰처럼 글, 작업 일지, 작업물을 태그와 링크로 이은 그래프를 홈과 /graph 에 넣었다.

Commits

  • 커밋 1 — 그래프 뷰 (홈, /graph)
  • 커밋 2 — 본문 위키링크

연구 기록이 쌓이면 글 목록보다 연결이 더 중요해진다. 어떤 셰이더 실험이 어떤 결정으로 이어졌는지를 한눈에 보고 싶어서, Obsidian 의 그래프 뷰를 블로그로 옮겼다.

커밋 1 — 그래프 뷰 (홈, /graph)

결정 빌드할 때 글 · Devlog · Works 와 태그로 그래프 데이터를 만들고, 브라우저에서는 d3-force 로 캔버스에 그린다. 홈 첫 화면은 슬로건 대신 수채화 배경 위에 이 그래프를 띄운다.

이유

  • 노트는 노드, 태그는 작은 노드, 본문의 [[위키링크]] 는 노트끼리 직접 잇는 선이 된다. Obsidian 에서 쓰던 방식 그대로 글을 쓰면 연결이 생긴다.
  • 그래프 데이터는 빌드 때 만들어 페이지에 넣는다. 정적 사이트라 서버가 없어도 된다.
  • 노드가 수백 개가 되어도 버티도록 SVG 대신 캔버스로 그린다.
  • 홈의 큰 슬로건과 버튼은 지웠다. 첫 화면에서 실제 기록의 구조가 보이는 편이 소개 문구보다 정확하다.

동작

조작 결과
노드에 마우스 올리기 그 노드와 이웃만 밝게, 나머지는 흐리게
노드 누르기 해당 글로 이동
노드 끌기 위치 이동 (놓으면 다시 물리 시뮬레이션)
휠 · 핀치 · 빈 곳 끌기 확대와 이동 (/graph 에서만, 홈에서는 페이지 스크롤 유지)
확대 라벨이 점점 나타남

대안

  • Quartz 로 전환: 그래프가 기본으로 있지만 지금 사이트를 버려야 하고, 다른 Quartz 사이트와 비슷해진다.
  • Cytoscape.js: 기능은 많지만 이 용도에는 무겁다. d3-force 는 필요한 모듈(force, zoom, drag, selection)만 가져올 수 있다.

커밋 2 — 본문 위키링크

결정 글 본문의 [[대상]], [[대상|표시 이름]] 을 빌드할 때 실제 링크로 바꾼다. 대상은 파일 이름이나 글 제목으로 찾는다. 예: 어제 만든 블로그 구축 기록, 수채화 셰이더 #1 — 엣지 다크닝과 그래뉼레이션.

이유

  • 커밋 1 에서 위키링크는 그래프의 선이 되었지만, 본문에서는 괄호 그대로 보였다. 그래프에서 이어진 것은 글에서도 눌러서 갈 수 있어야 한다.
  • 대상이 아직 없는 링크는 지우지 않고 흐린 점선으로 남긴다. Obsidian 처럼 “앞으로 쓸 글” 의 자리를 표시해 둘 수 있다. 예: 툰 셰이딩 램프 정리

대안

  • 기존 remark 위키링크 플러그인: 대부분 파일 이름만 찾고 제목 매칭이나 컬렉션 구분이 없다. 필요한 기능이 작아서 직접 만들었다.
